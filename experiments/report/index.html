What it shows

Adding incident context does not change macro F1, but it roughly triples the false-positive rate (0.38% → 1.14%). The extra false alarms fall on benign events inside multi-event incidents (8.1% vs 2.6%).

The pattern holds at every window (60–900 s) and every seed. It supports the Run B conclusion under controlled conditions.

These figures are not directly comparable with Run B's headline numbers: the ablation uses one pooled event model, whereas Run B uses 13 per-source models and an incident-level model.

Part B

Does linking DNS logs and IDS alerts help on unseen captures?

This tests correlation across log types (Zeek connection logs, Zeek DNS logs and Suricata alerts) made from the same packet capture. It does not test independent device, gateway and cloud sensors.

Seven IoT-23 captures were re-processed from their original pcaps with Zeek 9.0.1 and Suricata 7.0.3, using one fixed ET Open ruleset. New connection records were matched to the IoT-23 labels by Community ID and start time. Training used captures 1-1, 3-1, 20-1 and 42-1; testing used 8-1, 21-1 and 34-1, all fixed before training.

What it shows

On captures the model never saw, every condition misses most attacks. Training attacks are mostly port scans, while test attacks are mostly command-and-control.

Within that hard setting, DNS context helps in every seed, and DNS plus alerts gives the largest gain in every seed. Alerts alone add nothing. The gain comes from catching more c2 connections (detection 11% → 45%).

Results vary strongly by seed, and the bootstrap covers only seed 42. The direction is consistent; the size is uncertain.

Limitations

  1. The log types come from one capture point, not from independent sensors.
  2. In capture 34-1, IoT-23's log has one row per packet (14,159 rows) for a single DDoS flow. Zeek 9.0.1, and Bro 2.6.4 checked separately, record it as 6 connections. So only 237 of 14,394 DDoS rows are in the test set.
  3. Only alerts at or before a connection's start are used. Three of the seven captures raise no alert at all.
  4. The 2026 ruleset postdates the 2018–2019 captures.
  5. The target is binary. DDoS appears only in test capture 34-1, and training has only 35 c2 rows.
  6. Seven captures from one lab, each with one infected device.
  7. The ablation settings used the package defaults and were not agreed with Dr. Shah in advance.
